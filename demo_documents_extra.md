# Дополнительные документы для тестирования записи демо

Используйте любой из них в форме «Добавить документ» — заголовок и текст
вставляются как есть. Каждый тематически похож на 5 автозасеянных, но не
дублирует их.

---

## Вариант 1

**Заголовок:** Правила проведения ретроспектив

**Текст:**
```
Ретроспектива проводится в конце каждого спринта, обычно по пятницам после обеда.

Формат: что прошло хорошо, что можно улучшить, какие действия берём в следующий спринт.

Ведущий ретроспективы меняется каждый раз — по кругу среди участников команды.

Итоги фиксируются в общем документе и проверяются на следующей ретроспективе.
```

## Вариант 2

**Заголовок:** Правила бронирования переговорных

**Текст:**
```
Переговорные бронируются через общий календарь не менее чем за 15 минут до встречи.

Если встреча отменяется, бронь нужно снять — иначе комната считается занятой следующие 30 минут.

Переговорная на 2 этаже оборудована проектором, на 3 этаже — только для звонков без презентаций.

Максимальная длительность непрерывной брони одним человеком — 2 часа, дальше нужно повторное бронирование.
```

## Вариант 3

**Заголовок:** Регламент код-ревью

**Текст:**
```
Ревью запрашивается сразу после открытия pull request, не позже конца рабочего дня.

Ревьюер отвечает в течение 4 рабочих часов — либо комментариями, либо одобрением.

Критичные замечания (баги, безопасность) блокируют мерж; стилистические — не блокируют, оформляются как предложения.

Автор PR сам мержит после одобрения — ревьюер не мержит чужой код.

Если ревьюер не отвечает больше суток, можно попросить ревью у любого другого разработчика в команде.
```

За 3 рабочих дня до отпуска нужно назначить человека, который подхватит текущие задачи.

Все открытые задачи переводятся на замещающего в трекере с коротким описанием статуса.
